# AgentCF 多代理自进化去偏：后续实验执行计划

> **冻结历史计划。** 本文保留 2026-10-12 的研究设计与当时状态，未按工程进展重写；下文“未启动”“尚未就绪”等表述属于当时快照，未来产物和验收条件也不代表已经完成。当前目录、统一入口及 v4 双环用法见 [README](../README.md) 与 [代码导读](代码导读.md)。后续研究仍需实际证据，工程演示通过不等于本计划的 H1–H3 已成立。

版本：2026-10-12 / v0.1。状态：研究设计；未启动模型实验。D1–D7 从实际开始执行之日计时。

**首周交付目标：可复现的机制证据、一个有明确对照的去偏算法候选、受约束自动实验闭环，以及条件允许时的一次独立元评价。** 论文主张以 bias/debias 为中心；有限 RSI 是待验证的方法，不能预设成立。

## 2. 要证实的三件事

| 编号 | 假设 | 支持证据 | 会推翻或缩小主张的情况 |
|---|---|---|---|
| H1 机制 | 某些曝光/输入位置条件下，记忆更新及共享物品路径增加超出偏好参考的热门倾斜 | 配对因素交互 + 记忆轨迹 + 切断共享路径的对照；同时寻找缓解和无影响条件 | 冻结记忆与正常更新无稳定差异；效果完全由静态排序/候选支持造成 |
| H2 去偏 | 可追溯的重放修复比固定保护规则更好地减少该倾斜，并保留推荐效用与有效协同 | 主偏差降低 ≥10%；NDCG 相对下降 ≤1%；修复范围消融和成本比较 | 只靠拒绝写入、删除全部共享状态、更多调用或测试集选择获胜 |
| H3 有限 RSI | 更新后的 ψ 在未见环境、相同初始 θ 和预算下，更容易产生合格去偏版本 | 冻结 ψ_old/ψ_new 后的独立元评价；档案增长对照 | 只在开发环境进步；只多用了预算；档案增长已解释全部收益 |

H1 并不假定 AgentCF 一定放大偏差。原文已分析位置/流行偏差，不能将“发现它有偏差”单独视为新贡献。[AgentCF 原文 §3.3](https://arxiv.org/html/2310.09233v1)

**执行优先级：复现条件 → H1 → H2 → 固定自动化 → H3。** 若 H1 不支持预设链条，保留负结果，转向解释偏差被缓解的条件；不能修改模拟器直到新方法获胜。若 H2 尚未成立，H3 只做工程演示，不作 RSI 效果结论。

## 3. 数据和分区

### 3.1 首周两条数据线

| 数据线 | 获取与构建 | 用于什么 | 不能声称什么 |
|---|---|---|---|
| 作者小基准 | 从固定作者 commit 补齐代码、CDs.item 与依赖；先 CDs-dense，其他子集是扩展 | 主路径复实现、给定候选排序、真实日志上的顺序扰动与方法迁移 | 曝光已识别、未交互就是厌恶、真实用户长期福利 |
| 可控语义世界 | 外部程序生成物品属性、偏好、曝光、反馈；用忠实模板呈现属性，禁止被评 LLM 同时制造真值 | H1/H2；受控反馈下的闭环；H3 的新环境 | 真实人类偏好、真实平台上的因果效果 |

作者基准保留原 train/valid/test 协议作参考结果，原 test 封存。另建研究用开发分区时，只使用原 train/valid，按每个用户的可用前缀划分，记录全局共享状态更新顺序。缺时间戳时明确采用确定性的用户轮转协议，不能写成全球真实时间线。初次测试训练阶段不使用 valid 的目标事件；是否把 valid 作为最终 test 前的可见历史须在冻结协议中声明，并统一应用于各方法。

当前核查只有审计源码快照，以及 CDs-dense 的 500/100/100 条 train/valid/test 与候选文件；完整源码包、物品元数据和兼容环境尚未就绪。现代 DeepSeek 实现属于**同机制复实现**，不承诺重现旧模型论文数值。[作者代码](https://github.com/leoleojie/AgentCF-WWW)

### 3.2 可控世界构造规则

1. 世界种子决定用户偏好、物品可读属性、共享交互图及外生随机量。生成规则独立于被评方法。初版采用静态偏好；偏好漂移作为后续挑战。
2. 设置低/高曝光倾斜；每个物品保留正的曝光支持，记录实际 `q(i|u,h_t)` 及来源。热门集合 H 来自共同前置期，随后冻结；反馈形成的动态流行度另行记录。
3. 设置“热门与偏好基本无关”及“热门确实有较高效用”两个预登记层。方法不应把用户真实喜欢的热门物品一概压低。
4. 反馈由冻结的偏好函数和外生随机量产生。推荐器只看合法可见信息；隐藏偏好、潜在反馈和评测标签仅给评价程序。偏好真值不能作为修复器的答案。
5. 训练曝光集合可以变化；用于比较的评价候选面板固定，独立于各臂推荐结果。初版可控世界每面板 20 个候选、评 NDCG@10；作者线保留其 10 候选协议，两个数值分别报告。
6. 先做固定日志的开环回放，定位记忆效应；再做推荐影响后续曝光的闭环。闭环允许轨迹分叉，复用同一外生生成机制，不能强求不同动作得到相同反馈。

首轮规模是工程起点，**不是统计充分性的承诺**：

| 批次 | 规模建议 | 用途 |
|---|---|---|
| 无模型协议检查 | 极小固定事件与确定性 mock | 检查计分、隔离、依赖修复、非法输出和预算边界 |
| API smoke | 4 用户、12 物品、每用户 2 个事件；先两臂 | 确认一次选择→反思→记忆→评测可以闭合；初始最多 100 请求 |
| 独立 pilot | 3 个世界种子；每世界 12 用户、60 物品、每用户 4 个事件 | 估算方差、信号分辨率、调用数、吞吐；不用于选新方法赢家 |
| 主实验 | 独立于 pilot 的世界；重复数和规模经 pilot 冻结 | 比较预登记假设；不足以支持 1% 不劣时报告 inconclusive |

若主实验所需重复超过一周吞吐，首周交付探索性效应和区间，正式验证延后；不放宽 1%/10% 门槛以换取“通过”。

### 3.3 分区与信息流

- **task-train**：更新任务记忆 M。
- **search-dev**：诊断、提出干预、选择 θ；允许自动系统反复使用。
- **promotion-dev**：有限次数检查晋升；若结果回流到搜索器，该分区也是开发数据。
- **final-test**：冻结每种方法选中的唯一版本后运行；不反馈给下一代。
- **meta-development worlds**：用于修改 ψ。
- **meta-test worlds**：保留未见曝光强度、组合或语义域；每个世界仍有供改进器使用的开发区和外部评价的测试区。

每个方法/种子使用完整独立的用户与物品记忆池。共享物品引入干扰，不能在同一池中把用户随机分两组当作独立对照。统计重复单位是独立世界/完整池；用户和时间点是池内重复测量。作者小基准多次运行只反映给定数据上的条件变异，不等于多个独立真实数据集。

## 4. E0–E6：具体怎么跑

### E0 复现条件与安全调用，D1

**先完成最少修复：** 补齐作者固定版本；建立独立兼容依赖环境；旧 SDK 调用迁移；去除密钥/完整配置打印；每请求设超时及最多 2 次重试；唯一物品 ID 排序；统一非法输出计分；基本事件与记忆快照日志。先走作者 basic 推理，首周主线不增加 RAG/embedding 后端。

保留两种记录：①作者机制参考实现；②所有后续方法共用的运行/评测修正版。修复差异逐条列出。后续算法收益相对于②衡量，不把 SDK/解析/协议修复算作去偏贡献。

**验收：** 两臂能从同一快照独立运行；失败后可恢复；选出的 ID 来自合法候选；密钥不出现在日志；同一失败候选不会影响下一试验。100 请求 smoke 不通过便停，不启动八单元长批次。

### E1 pilot 与协议冻结，D2 前半

只用基线、确定性算子和固定探针估计噪声及吞吐；不比较新方法后再决定样本量。记录每类事件实际调用数、输出长度、有效响应、失败率、每世界运行时间和主指标噪声。

然后生成 `protocol.json`：模型配置、数据/代码 hash、候选面板、种子与分区、主比较、次指标、正式重复数、总 token/时限、统计方法、最多晋升次数。确认性试验前冻结。需要修改时增加协议版本，将此前结果标为探索性，重新保留测试集。

### E2 机制与组合，D2 后半–D3

基础 2×2×2 八单元见 [实验矩阵.csv](../configs/mechanism_matrix.csv)：

| 因素 | 水平 0 | 水平 1 |
|---|---|---|
| A 曝光倾斜 | 低 | 高 |
| P LLM 候选输入位置 | 配对平衡 | 固定热门优先 |
| M 任务记忆 | 同一初始记忆冻结 | 作者机制正常更新 |

同一世界跨八单元配对；随机交错运行顺序，避免 API 时间变化与某个实验臂绑定。位置实验保持候选 ID 和文本完全相同，只改排列。冻结记忆时仍提供该臂合法可见事件，不能额外删掉信息造成假对照。

**主比较：** 分别在 P 两个水平计算 `Δ_M=[B(A1,M1)-B(A0,M1)]-[B(A1,M0)-B(A0,M0)]`，再比较 P 的差异。这是因素交互；不是自然中介效应的完整识别。

确认性 H1 主对比预设为位置平衡时的 Δ_M；位置组合差异及时间轨迹是机制扩展。所有单元均报告，避免只展示最有利条件。

**必要消融：** 在预登记的高倾斜单元，补只更新用户记忆、只更新物品记忆、切断跨用户共享物品写入。加入语义上合理热门的负对照，检查误诊。基于 pilot 的预定规则选择验证单元，不能依据正式测试最大的差值选图。

**输出：** 偏差随交互步变化的曲线、因素交互表、A→物品→B 的可追溯案例、没有放大/出现缓解的条件。无稳定记忆路径信号时停止“传播导致放大”的主张。

### E3 固定去偏算法，D3–D4

先将 θ 固定，避免把算法比较和搜索能力混在一起。最少比较如下：

| 臂 | 内容 | 排除的解释 |
|---|---|---|
| B0 | E0 的 AgentCF 共用修正版 | 基线 |
| B1 | 未知负反馈保护 + 来源/类型写入约束 | 简单固定保护已足够 |
| B2 | 固定流行度重排/校准，阈值只用开发区选 | 输出层去偏已足够 |
| B3 | 只修复当前用户/物品状态，不追溯下游 | 下游依赖修复没有额外价值 |
| B4 | 依赖感知重放修复候选 | 拟议新方法 |
| 反例 | 冻结或清空共享记忆 | 靠停止学习/取消协同获得假去偏 |

B1 各组成部分在定位需要时再拆；不一开始做所有算子的全排列。若采用 IPS/SNIPS，只在生成概率已知、支持条件满足的模拟分支使用，并作为单独算子；不能把物品频次倒数当真实 propensity。

**B4 的最小算法合同：**

1. 事件只追加；记忆保存版本、来源事件及实际读取过的状态版本。读依赖构成保守 DAG，不直接声称是因果图。
2. 用可见的曝光统计、反馈类型和顺序敏感性触发 probe；“曝光多”只能触发审查，不能直接判定用户不喜欢。
3. 在影子分支重放已观察事件，改变合法的输入排列/解释规则，比较记忆和排序。不得伪造未曝光项目的反馈。
4. 修订有问题的源推断后，按事件顺序重建依赖后代；事件事实本身不删除。只修当前一句而留下其下游旧推断作为 B3 消融。
5. 恢复后验证有效偏好学习、跨用户协同、效用和成本；预算不足时拒绝或限缩修复，记录未覆盖部分。

**曝光反事实的边界：** 顺序重放不等于识别未曝光物品的偏好。只有可控世界评价器可用生成机制计算相应反事实；修复器不得读取隐藏答案。真实日志上的“修复有效”首先是稳定性/排序结果，不能自动升级为曝光因果识别。

**继续条件：** B4 相对 B0 达到 10% 主偏差目标、1% 效用约束及有效记忆守门，同时优于最有竞争力的固定对照或呈现有价值的成本/效果差异。若 B1 已足够，优先保留简单方案并重新审视贡献。来源门控/层级监督与 ConnACF 有直接近邻关系，不能单独作为创新声明。[ConnACF](https://arxiv.org/html/2608.03272v1)

### E4 固定自动化与多 Agent，D4–D5

先固定 ψ0，构建“诊断→假设→有限改动→隔离运行→外部评价→接受/拒绝→归档”闭环。只允许改 θ 白名单，评价器和真值不在该进程可读范围。首版使用文件/JSONL 与最小命令入口，不建设通用多代理平台。

| 对照 | 固定职责 | 搜索预算 |
|---|---|---|
| S0 | 随机/固定规则选择同一算子集合 | 与其他搜索器相同上限 |
| S1 | 单 Agent 执行诊断、设计、实现、反证检查 | 相同可见证据、工具与总 token 上限 |
| S2 | 多 Agent 按职责隔离上下文，ψ 固定 | 相同上限；角色间通信也计费 |

初始每次搜索最多 8 个候选；token/墙钟上限用 E1 测得的候选成本冻结。哪个上限先到便停止，不给失败方法追加机会。8 个不是统计样本量，也不是预期成功次数。

候选从同一父 θ/完整记忆快照分支，只改一个主要机制。完整保留失败、超时、拒绝与回滚。人工/Agent 都不能从 final-test 选择赢家。比较选中版本的偏差/效用、达到约束的成本和合法完成率；没有协作收益时采用 S1。

### E5 一代元改进与独立评价，D6，满足前置门槛才进行

只开放 ψ 的 probe/干预选择规则及有限试验次序；不能修改执行器、预算或晋升标准。

1. ψ0 根据 meta-development 的成功/失败轨迹提出 ψ1，并留下可执行策略差异。
2. 在新的开发世界实际用 ψ1 产生下一代 θ 候选，证明它进入改进链路；仅生成一段总结不计元更新。
3. 冻结 ψ0、ψ1，补“ψ0 + 相同经验档案”对照；必要时补同预算随机策略变化。
4. 在封存 meta-test 世界，各组获得相同 θ0、可见证据、合法算子及预算。每组只在该世界开发区搜索并选一个 θ，再由外部程序评价该 θ 的测试结果。
5. 报告有效干预发现率、测试主偏差/效用、失败率、消耗；元更新自身的费用计入全生命周期成本。

首周主元指标建议为**固定预算内产生满足去偏与效用点门槛的版本比例**，同时保留效应与置信区间。正式重复数由 E1 确定；数个世界仅为探索。点门槛候选不能冒称统计晋升。

通过只能支持“一次受限元更新的迁移证据”。持续递归、稳定跨代加速需要至少后续独立代际与新世界验证。[HyperAgents 元评价参照](https://arxiv.org/html/2603.19461v1)

### E6 冻结报告与第二模型，D7

冻结每种搜索方法在开发区选中的唯一版本；final-test 只运行预登记比较。第二模型重跑关键 E2 对比与 B0/B1/B4，不能仅重评赢家 prompt。若时间不足，明确列为后续任务，不能称跨模型已验证。

交付主表、机制曲线、路径消融、质量—偏差—成本关系、元评价、失败案例和复现清单。自动化管线可成功运行与算法效果成立分别验收。

## 5. 指标和晋升规则

### 5.1 主偏差的可计算定义

仅在有冻结偏好真值的模拟世界定义如下主指标。设 H 为前置期冻结的热门集合；`d_j=1/log2(j+1)`。在共同评价候选面板上：

`h_R(u) = Σ(j=1..10) d_j · 1[rank_R(u,j)∈H] / Σ d_j`

`h_*(u)`：按隐藏真实效用排序的参考列表，使用同一面板、相同折扣和预登记平局规则。

`B_pop = mean_u max(0, h_R(u) - h_*(u))`

它衡量**本研究参考下的额外热门倾斜**，不是对所有流行度偏差的通用识别。另报有符号差、头尾效用及“热门合理”层，避免单一方向掩盖过度压低热门。

相对改善 `r_B=(B0-Bnew)/B0`，目标 `r_B≥0.10`。若 B0 为零或低于预登记可测下限，该世界标为“无足够可降低偏差”，不除零、不把低基线波动算巨大相对收益。仍报告该世界效用、误报和绝对偏差；它计入覆盖/失败说明，不能挑掉以提高总体成功率。

作者真实日志没有 h_* 真值，不能计算同义的 B_pop。该线只报排序、输入位置敏感性和描述性热门倾斜，不套用模拟因果结论。

### 5.2 必须一起报告

| 类别 | 指标与口径 |
|---|---|
| 推荐效用 | NDCG@10 主指标；@5、Hit/Recall 辅助。模拟使用冻结相关性；作者使用日志目标，两线分表 |
| 输入位置 | 同一面板在平衡排列下 Top-1 不一致率与排序距离；不与真实 UI examination 混用 |
| 记忆 | 可核验属性的推断错误/无支持率、有效覆盖、共享路径影响范围；自由文本标注单独校准 |
| 学习守门 | 偏好证据积累后的效用变化、有效偏好覆盖；防止全部拒写的假改善 |
| 成本与可靠性 | 全部输入/输出/推理 token、缓存命中、API/embedding 请求、重试、墙钟、失败及修复范围 |
| 自动化/元改进 | 合格版本发现率、达到目标的成本、未见环境效应；θ/ψ 版本血缘分别记录 |

基线自由文本与新方法结构化状态使用同一只读评测口径。结构来源 ID 仅说明引用了某事件，不证明自然语言推断正确。首周自动可核验指标为主；自由文本辅助标注若未经人工/结构真值校准，不进入晋升奖励。

非法/重复/漏候选输出采用预登记失败计分，固定分母；不通过缩小合法输出样本来提高 NDCG。主指标、位置/覆盖守门和成本分别检查，不能把它们加成一个分数互相抵消。

### 5.3 1% 约束与不确定性

固定比较基线是同数据/候选/模型协议下的 B0，不随候选变化：

`r_U=(U_new-U_B0)/U_B0 ≥ -0.01`

相对于父版本也记录退化，防止多次每代下降 1% 后累计突破初始基线。U_B0 为零时该协议不可用于相对不劣判断。

- **探索性合格**：点估计 r_U≥−1%、r_B≥10%，且其他守门满足。状态名为 eligible。
- **统计支持**：预登记的单侧置信下界同时达到效用与偏差目标；按世界/记忆池的配对重复估计。小样本比值区间不稳定时，不强行使用普通逐用户 bootstrap。
- **不确定**：区间跨门槛为 inconclusive；“下降不显著”不等于证明不劣。
- **选择与多次晋升**：开发搜索可以多次使用开发区；确认性比较提前限定主对比和检验次数，必要时控制多重检验。final-test 不用于再选择、调阈值或追加到显著。

重复数由独立 pilot 的配对方差与预设精度/功效计算；尤其 1% 界值很严格，100 用户或 3 次 API 重复不保证足够。正式批次冻结固定规模，不能边看测试显著性边停止。

统计分析先按以下约定登记，细节由 E1 的分布/吞吐检查落实：

- 世界等权；预登记的“热门合理/无关”等层使用固定权重。主效果对所有预定世界汇总；无偏差世界单独显示，不据结果删世界。
- 正式检验用每世界的 `D_U=U_new−0.99·U_B0` 和 `D_B=0.90·B_B0−B_new`，检查均值的单侧 95% 置信下界是否为正，避免直接对近零分母作不稳定比值检验；相对变化仍用于解释效果。
- 误差估计保留世界配对与分层；正式重复数按 pilot 方差、效用差真值为零时的 1% 不劣界及 80% 目标功效规划，并对偏差指标做精度检查。只有 3 个 pilot 世界不足以精确估计尾部风险，应作方差敏感性分析。
- H2 主比较预登记 B4 对 B0；与开发区选定的最强固定去偏对照作第二比较，涉及多个确认性结论时预登记校正。其他消融首先作机制解释，不把所有表格都宣称显著。
- H3 对每世界的“开发区选中版本”作配对比较，测试区从不返回候选排序。首周元评价默认探索性；正式样本足够且协议冻结后再作确认性声明。

位置/记忆覆盖守门的具体容忍度在 E1 后、B4 效果比较前登记，并在主报告展示原始指标及区间；它们不是可被 10% 偏差收益抵消的奖励项。

## 6. 多 Agent 分工与运行边界

| 角色 | 任务 | 可见信息 / 产物 |
|---|---|---|
| 推荐用户/物品 Agent | 依当前 θ 更新 M、输出排序 | 合法历史及各自允许状态；ID 排序与记忆差异 |
| 诊断 Agent | 提出偏差机制并找替代解释 | 开发证据；诊断、未知项、建议 probe |
| 干预/实现 Agent | 提出单一可证伪改动并生成有限策略 diff | 算子白名单；假设、版本、成本预期 |
| 反证复核 Agent | 找误诊、效用损失、状态不一致与信息泄漏 | 候选及开发证据；反例和必要对照 |
| 外部控制程序 | 分区隔离、预算、执行、评测和晋升 | 受保护数据；机器计算指标与不可改的决定日志 |

研究层首版三种职责即可；不是每类偏差都部署一名 Agent。角色可以使用同一个固定模型，隔离上下文。并行提假设/读证据；状态写入、预算登记与晋升由外部程序串行控制。实验臂可以并行，但每臂内部共享物品更新顺序固定。

候选提交最少包含：机制、证据来源、允许改动、预期方向、反证条件、预算和父版本。自动改动先限制为声明式规则/受限策略；若允许执行代码，进程的文件/网络/工具权限须真正限制并验证，不能只靠 prompt 或路径白名单。

## 9. 首周结束交付和后续扩展

**首周交付物：**

1. 可执行的最小实验入口、锁定依赖、代码/数据/model/prompt 清单；每个结果能追到一次 trial。

4. 一份初步研究报告：哪些假设被支持、反证或尚不确定；工程修复与方法改进分开。

**第二阶段顺序：**

1. 若机制和方法有信号，扩展正式世界数、第二语义域和异构模型；增加一个不同记忆推荐实现，降低对 AgentCF 的依赖。
2. 补传统推荐器作为排序效用/成本参考；它们没有相同语言记忆，不能冒充记忆路径消融。
3. 使用 KuaiRand-1K 的随机反馈与语义补充进行受限外部验证；先核对许可、视频 ID 对齐、文本时间、支持与概率含义。不将 `is_rand` 当曝光概率。[KuaiRand 官网](https://kuairand.com/)
4. Coat 可作为静态随机评分校准支线；不伪造长期序列。公平、从众等偏差在目标/属性/识别条件齐备后纳入统一接口。
5. 扩展 ψ 的独立代际评价；若元更新只带来开发集优势，论文收束为机制+去偏，不强挂持续 RSI 标签。

创新仍需围绕具体机制查新：**可见证据触发的反事实式重放、协同记忆依赖修复、受效用约束的干预选择，以及改进策略的独立迁移评价。** 工作流和 prompt 编排是实验工具；新颖性、效用和外推性尚未证明。
