# 推荐系统研究员：官方真实数据可行性验证

主批日期：2026-10-14；补充检查与交付核查日期：2026-10-15。本报告对应本次实际运行的记录与随后发现问题后的代码修改。

**系统已经完成一次真实数据、真实模型、实际推荐器和独立评分组成的研究流程。Coat 上存在满足约定点门槛的改法；KuaiRand 上两个冻结改法都未保住质量。因此，目前可以确认研究流程可执行，不能确认持续自主迭代已经实现 RSI。** 真实运行还暴露了跨任务证据误读，修复后的补充检查需要分别记录，不能用它覆盖原结果。

本文把三件事分开判断：程序完成了哪些步骤；某个推荐改法是否有效；研究系统自身是否比原策略更会研究。前一件成立，不能代替后一件成立。

## 1. 数据从哪里来，实际用了哪部分

Coat 直接下载自 [Cornell 作者发布页](https://www.cs.cornell.edu/~schnabts/mnar/)。作者提供训练、测试评分矩阵、估计观测概率和用户物品属性。本轮使用其评分文件，不把估计观测概率当成已知真实概率。原始 ZIP 的 SHA-256 为 `6073d0b515ed1f6e830e4fead66dc76ad7991a7553eaa58e228b234a9d19daed`；原文件和下载来源记录于本地 `source.json`。

KuaiRand 使用 [作者官网](https://kuairand.com/) 指向的 [Zenodo 数据记录](https://zenodo.org/records/10439422) 中的 Pure 版本，原始压缩包 SHA-256 为 `c814bf6f3624c0cfae83c57de3df26b2ed206e5c57bab4c4dcbfabbabe20cbf0`，MD5 与作者公布的 `0820331067a3784d9691136f772b35a7` 一致。Pure 保留随机候选池中的日志，序列不完整，适合这次较小规模的协同过滤研究，不能用来声称完整还原长期反馈。

实际使用情况由读取器计算，下面不是照搬官方总量：

| 项目 | Coat 主批 | KuaiRand 主批 |
|---|---:|---:|
| 用户组 | 290 名已知用户 | 根据训练期 ID 和种子选择 200 名用户 |
| 物品目录 | 300 | 7,583 |
| 训练记录 | 6,960 | 8,334 |
| 开发记录 | 2,065 | 2,459 |
| 冻结验证记录 | 2,209 | 5,511 |
| 验证面板有观测用户 | 290 | 198 |
| 验证面板质量可评价用户 | 276 | 146 |

Coat 的 `0` 表示没有观察到评分，读取时剔除。随机评分中与训练重叠的 366 个用户物品组合先移除，剩余组合按固定种子 `20261014` 在每位用户内部划分开发和验证。因此它是已知用户的新物品组合评价，不是时间外推。

KuaiRand 的 `is_click=0` 是已经曝光后记录的零反馈，必须保留；该字段在不同界面中可能表示点击或有效播放，不能统一解释成“喜欢”。作者对这一字段和 Pure 的适用范围有明确说明。[官方字段和版本说明](https://kuairand.com/)

KuaiRand 训练用 2022 年 4 月 8—21 日普通推荐日志，开发用 4 月 22—30 日随机曝光，验证用 5 月 1—8 日随机曝光。用户根据训练期 ID 选择，不根据未来有没有点击选择。每人最多保留 200 条最近训练事件；训练已见组合及开发、验证重叠组合被剔除，同分区重复组合保留最早反馈。热门计数只使用保留的训练记录，没有读取整月统计、未来点击数或随机验证评分作推荐特征。

两份数据的缺失反馈都继续保持未知。评价只在真实观察过的候选物品中进行，不补造完整用户喜好表。

## 2. 为什么接入第二个普通推荐器

本轮研究对象是新增的 **ItemCF**：根据用户共同给予正反馈的物品计算相似物品，在本机 CPU 上排名。这样可以快速检验“研究员能否读真实反馈、安排实际改法、接受外部结果”，无需为一次流程检查重跑整篇 AgentCF 实验或占用 GPU。

AgentCF 的原路径仍然保留；ItemCF 结果不代表 AgentCF 复现结果。两个推荐器为同一研究流程提供不同研究对象，后续可以比较观察到的问题是否只存在于某个推荐器。

ItemCF 只用训练反馈建立相似度。排名阶段接收用户与候选物品编号，开发和验证标签只交给评分程序。允许研究员安排的改法是：保留原版、全局热门惩罚、按用户训练历史调整惩罚强度。Coat 的热门来自“被评分频次”，不是实际曝光次数；KuaiRand 的热门来自本轮保留历史的曝光频次。它们都只是可能受平台选择影响的历史代理。

这次自主研究是模型安排已经实现的改法，尚未开放任意编写新算法，也未在线上向用户投放。

## 3. 模型计划怎样变成实际研究

每轮有两次角色调用：先计划，再读取程序结果作总结。计划必须给出主要解释、竞争解释、实际动作、强度、预期和可以推翻它的结果。普通程序执行改法、产生排名、计算指标。模型不能自己填写评分。

Coat 带历史臂有一条可审查的实际衔接链：

| 轮次 | 实际动作 | 总结提出的下一动作 | 后一轮是否采用 |
|---|---|---|---|
| 1 | 全局热门惩罚，强度 0.05 | 强度 0.1 | 是 |
| 2 | 全局热门惩罚，强度 0.1 | 强度 0.2 | 是 |
| 3 | 全局热门惩罚，强度 0.2 | 强度 0.4 | 该源任务到此结束，没有第四轮 |

无历史臂同样获得三轮提案和总结机会，但前一轮结果不输入下一轮，三轮实际都选择 0.05。相同改法的 CPU 排名和评分被复用，仍消耗候选提案名额及计划、总结请求，不算独立重复。这说明反馈连接确实会改变后续安排，但不能由提案更多样就断言效果更好。

开发完成后，程序从符合点门槛的候选中选择一项，先写入 `frozen_candidate.json`，再对留出反馈评分。留出阶段不让模型重选强度。固定规则对照预先使用 0.05、0.1、0.2 三个强度，不调用模型。

随后模型根据 Coat 的开发和冻结验证修改下一任务的研究策略。实际变化是：证据重点从总体情况改成质量受损用户，优先动作从全局惩罚改成按用户调整；强度网格仍是 `[0, 0.05, 0.1, 0.2, 0.4]`，没有变化。程序把证据重点用于案例选择，把优先动作作为首轮建议，而非强制执行。KuaiRand v1/v2 使用相同候选轮数、相同数据和同等源任务经验。

因为 Coat 留出结果被用于这次策略修订，它现在也是整个研究系统的学习经验，不能继续称为整个研究系统最终未见的数据。KuaiRand 留出反馈在该次候选冻结前没有用于选方案。

## 4. 实际效果：流程成功不代表 RSI 成功

质量采用观察候选内的 NDCG@5：已观察反馈更好的物品排得更靠前，得分更高。偏差代理采用“面板额外热门倾斜”：热门物品实际获得的加权展示份额，超过按本面板反馈形成理想排序时应有的份额多少。同反馈物品的理想热门份额取平均，避免物品编号的任意次序制造假差异。

两个独立点门槛是：质量至少保留原版的 99%，额外热门倾斜至多是原版的 90%。另行报告用户配对重抽样区间，它描述同一观察面板上结果的不稳定程度，不自动消除多候选选择影响。

以下均为冻结候选的留出验证结果：

| 研究安排 | 冻结动作 | 原版质量 → 候选质量 | 原版倾斜 → 候选倾斜 | 点门槛 |
|---|---|---|---|---|
| Coat 带历史 | 全局惩罚 0.2 | 0.694411 → 0.697362 | 0.063118 → 0.037169 | 通过 |
| Coat 无历史 | 全局惩罚 0.05 | 0.694411 → 0.697876 | 0.063118 → 0.042176 | 通过 |
| Coat 固定规则 | 全局惩罚 0.2 | 0.694411 → 0.697362 | 0.063118 → 0.037169 | 通过 |
| KuaiRand v1 | 全局惩罚 0.4 | 0.302981 → 0.260763 | 0.132856 → 0.014260 | 质量失败 |
| KuaiRand v2 | 按用户调整 0.05 | 0.302981 → 0.292128 | 0.132856 → 0.084803 | 质量失败 |

Coat 带历史臂质量差异为 `+0.002951`，95% 区间约 `[-0.015510, +0.020530]`；倾斜差异为 `-0.025949`，区间约 `[-0.033357, -0.018706]`。质量区间跨过 0，且负侧超过约 1% 的原版质量，因此不能用它证明“质量损失不超过 1%”。均值点门槛通过与这样的统计证明是两件事。

带历史臂与固定规则的冻结动作、留出指标完全相同，不能声称研究员超过了固定规则。带历史相对无历史的倾斜更低，但质量均值也略低，仍需更多任务和重复比较，不能把一次差异写成长期优势。

KuaiRand v1 质量下降约 13.9%，v2 约 3.6%，两者都超过允许的 1% 损失。v2 相对 v1 多保留 `0.031365` 的质量，同时额外热门倾斜增加 `0.070543`。这是取舍变化，不能称为修订策略全面胜出。

本次专门测试热门倾斜代理，没有覆盖所有 bias 类型；没有证明因果机制、全目录真实偏好改善、线上收益或长期反馈收益。当前资料最多支持小规模可行性和探索性策略迁移。

## 5. 真实运行暴露的科研解释问题，以及怎样修改

原运行记录完整保留。读原始计划和总结发现四类问题：

1. **把源任务的用户与阈值当成当前证据。** KuaiRand 的计划引用 Coat 用户 `216`、`0`，部分预测继续使用 Coat 基线质量 `0.6923` 和门槛约 `0.6854`；当前 KuaiRand 开发基线实际约 `0.4503`。跨数据匿名编号不能配对。
2. **由相同损失数值推断用户损失转移。** 两份数据里出现相近 `-0.63` 的差异，不能据此说明损失从一批用户转移给另一批用户，也不能把不同任务的强度档位当成同一面板的逐用户比较。
3. **描述没有执行的实验。** 一轮实际动作为 `retain`，模型却谈论检验内容或共现的新算法。保留原版没有执行这些算法，新假设没有获得相应实验。
4. **扩大失败结论。** 少数已测改法的质量区间跨过 0，只表示当前差异不确定，不能推出“没有可用去偏机制”。六个挑选出的受损示例也不能代表全体受损比例。

这些错误属于研究信息传递和解释层，不是推荐器读取了留出标签。评分仍由程序按实际排名和实际观察反馈执行，原始数值仍可检查；对模型叙事、机制判断和策略迁移结论则需要降级看待。

针对真实失败，代码作了直接业务修改：

- 新增 `source_experience()`，跨任务只传前任务的政策轨迹、汇总指标和对照，不传用户案例及完整解释文字。
- 计划、总结标明 `current_dataset`，当前案例标明所属数据；阈值只从当前基线读取，来源任务经验不能冒充当前观测。
- 总结输入新增由全部可评价用户算出的受损、受益、未变人数和最大损失，避免从六个示例推断总体比例。
- 提示词明确解释实际执行的 `policy`，`retain` 仅为无改动；未测试的算法不能写成发现，不确定结果不能否定所有机制。
- `next_action` 与 `plan_handoff` 记录建议和真实动作；保留原版的强度规范为 0，避免把相同行动错记为没有采纳。

这类修改让研究证据更准确地进入下一轮，并非通过改评分规则或删掉失败结果来制造通过。原始代码快照和结果仍留在原运行目录。

## 6. 请求数、失败批与补充检查

主批 `official-study-20261014-v2` 理想安排是 21 次请求，实际为 **22 次**，包含一次额外重试。接口返回 22 次，未知用量为 0；记录的输入 token 为 165,025，输出 token 为 17,239。这里的 token 是模型处理文字的计量单位。`usage.json` 按固定历史价格假设给出的费用上界估算约 0.0702 美元，不是实际账单。

更早的 `official-study-20261014-v1` 在模型初始化时失败，原因是子进程没有取得密钥环境变量；没有开始模型请求，保留为 **0 请求失败记录**，不把它算成研究批次完成。修复了进程间环境变量传递后，另开 v2 目录，未覆盖 v1。

修复科研信息归属后，另开 `official-context-check-20261014`：种子为 `20261015`，从训练用户中重新选择 200 人，每个研究策略仅一轮，理想 4 次请求。它的目的只是在新任务信息下检查基线、案例和实际动作是否被正确解释。

第一次补充批失败：实际请求 4 次、返回 4 次、未知用量 0。第一臂计划和 CPU 候选评分已经完成，但总结连续三次返回 `next_strength=0.02`，不在当时允许的 `[0, 0.05, 0.1, 0.2, 0.4]` 中，触发 `SchemaViolation`，最终为 `InvalidOutput`；第二臂未开始。原输入未向总结角色明确展示研究策略，重试也没有指出具体错项。这次失败完整保留。

随后作了两处直接修正：总结也读取当前策略及允许强度；本地重试反馈指出字段名和可选值。网格外强度仍可作为后续研究问题提出，但不能冒充本轮可执行行动。另开 `official-context-check-20261015-v2`，沿用第一次补充批的同一用户组与数据划分，每策略一轮；硬预算设为剩余 4 次，合并主批和首次检查的实际请求计数后才启动。

第二次补充批已完整结束：实际 4 次请求、4 次返回，没有重试。模型正确引用当前开发基线约 `0.5386`，并区分 Coat 来源经验。v1 执行全局惩罚 `0.05` 后开发质量降至 `0.4932`、额外热门倾斜为 `0.0550`；v2 执行按用户调整 `0.05` 后质量为 `0.5068`、倾斜为 `0.0676`。两者质量点门失败，因此两臂都冻结 `retain`，留出质量均为原版 `0.334534`，倾斜均为原版 `0.132484`；它们没有新增去偏收益。保留原版在这里是研究失败后的正常结果，不能写成去偏通过。

**最终核实请求数：22 + 4 + 4 = 30，返回数 30，未知用量 0。没有继续付费调用。**

完成后审核仍发现解释问题：模型把原版与自身比较所得的零变化当成“之前执行了 retain”；还把 93 名质量可评价用户与另外 78 名零理想增益用户说成包含关系。这表明修正归属与格式并没有自动解决全部科学解释问题。当前交付又删除首次输入中虚构干预感的零变化量，改成单纯的原版水平，并明确这两类人数互不重叠。这最后一项修正已经通过本地专门检查，**没有再调用真实模型验证其解释效果**，不能说语言误读已彻底消除。

这两次补充检查也不构成严谨的修复前后效果实验：用户组、划分种子和候选轮数已经改变，原批每策略两轮，新检查每策略一轮。只能核验信息归属与流程，不应把指标差异归因于上下文修复，更不能凭一次修复称为 RSI 证明。
